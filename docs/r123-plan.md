## 3. R12.3-A：稳定性核查与最小兼容修复

这是后续建议首先启动的阶段；本计划本身不执行修复。

1. 建立开工文件哈希与变更清单，覆盖源码、未跟踪文件、依赖锁文件及旧证据。先复核工程门禁，再使用当前生产版本采集一组连续日志，避免旧构建与新源码混用。
2. 对几何转换、Clock、阴影及精度警告保存堆栈、触发阶段、频率和实际来源。仓库内 `toNonIndexed()` 调用只是排查入口，不能假定全部警告来自这些行。
3. 比较两种处理路线：业务调用确有冗余或旧 API 时，做局部修正；来自框架或依赖时，记录上游边界与可验证的最小适配。默认不升级 Three/R3F/React、不修改 node_modules、不过滤控制台；需要升级时单独列版本兼容方案。
4. 阴影回退按实际生效结果做前后同机位对照。Clock/精度提示若无法在当前依赖下安全消除，保留明确说明，不以更换渲染架构追求零警告。
5. 对当前桌面帧耗时进行至少 3 组重复采样，每组预热后连续 30 秒；固定视口、DPR、质量档、相机、正常动效和设备条件，记录平均/p95、长帧、档位、draw calls、三角形及 CPU/GPU 条件。截图、堆快照、强制 GC、人工压力不混入稳态采样。只有存在可复现差异时再采集热点轨迹；需要旧版对照时使用隔离副本，禁止重置当前工作区。

验收：每类警告都有来源和处理结论；如有修复，先保存复现/失败证据，再增加针对真实行为的回归测试。既有 308 项测试继续通过；类型、源码 lint、构建分别通过。业务错误为 0，warning 分类原样留存。相同几何/画质下应保持渲染量；性能若超出重复采样的波动范围，先解释差异，不能宣称零回退。

暂停条件：局部处理将迫使升级依赖、改写生命周期管理或改变阴影风格时，先交付具体取舍，再决定是否扩大范围。A 的未消除依赖提示可以作为已解释残留，不必阻塞 B。

## 4. R12.3-B：一个树形的自然感样例

范围优先为 `tuft` 小型树；只有复核证据更支持其他形态时才换目标。先检查 `floraGeometry.ts` 冠层顶点与 `MainIsland.tsx` 树干变换，确认顶端深色短段是否为树干露出、阴影或其他结构。

对照保留现状，并评估两种方案：

- **最小修整**：只处理已确认的不合理顶端和层间接缝，保留既有轮廓与层数。成本低，轮廓改善有限。
- **局部冠形试点**：在一个形态内调整层间嵌套、轮廓偏移和枝叶体量，使冠层更连贯；保留现有实例化、确定性生成与色彩体系。优先复用当前网格结构，需新增面数时列出增量和收益。

选择依据是同机位近景、中景和玩家视角的可辨识收益；无需收益时保留现状。不能仅靠缩放、增加随机噪声或堆叠更多锥体完成验收。形态级生成器会影响全部同形实例，必须枚举并复看这些实例，不能把生成器修改描述成只改一棵树。

验收：树冠、树干和根部完整可见，顶端结构能解释；两种观察距离及多个方向有真实前后图。首页 1440×900、2560×1440、390×844 构图继续通过。树木坐标、数量、通行净空及四形态分工保持；无新增材质或 draw calls 为首选，三角形增量如实记录。若修改几何，增加对应轮廓/顶端/实例范围的数值测试，不用实现细节快照代替行为验证。样例未通过前不扩展其他树形、岩石或全岛布置。

## 5. R12.3-C：北径收口与扩展条件评估

这是有条件阶段，**不默认扩展到其他道路**。

1. 保留 `approach-a` 已完成的宽向采样与覆雪颜色。在相同采样点、两侧低视角和真实步行视角重新区分实体抬高、地面穿插与真正悬空；同时核对铺装是否有足够侧壁表达。
2. 比较保留现状、仅补明确侧壁/边缘表达、调整局部视觉偏移三条路线。调整偏移会涉及解析面与可见面差异，必须先列视觉网格、玩家高度、碰撞、导航和其他共享消费者；不先写补偿逻辑。
3. 若玩家视角收益不足或必须改共享功能高度，交付“不扩展”的结论即可结束 C。若可通过局部视觉处理改善，则先另列具体修改文件与高度/宽度验收值。
4. 北径候选通过后，才评估是否有另一个入口存在同类、已测量的问题。C 径踏板和跨海 A/M 桥面不属于推广对象。

验收：旧 27 点可比，新增问题点有实际网格采样；保留真实最小/最大高差，不以平均值掩盖穿插。固定机位与实际往返均通过；共享工具未选中分支的原输出保持，C 径与路径契约不变。既有成果优于候选时明确回退候选。
