## 24 轮资源复测

首个综合组从完成探索的会话进入往返，第 1–23 轮为 2,554 个 DOM 节点和 4,579 个监听器。第 24 轮，浏览器的文档计数从 4 降到 1，DOM 从 2,554 降到 894，堆从 55.61 降到 20.84 MiB。原脚本比较末五轮最大与最小 DOM 数，跨度超过阈值并报失败。末轮的 GL 记录仍包含先前轮次，事件日志在这一段没有新上下文清空事件，下降符合旧文档被回收的表现。该组未采集文档时间原点或旧文档保留链，具体释放路径未确认。原失败和全部原始数据保留。

独立复测使用新标签页，沿用原 24 轮往返、强制 GC 与 DOM 断言，增加每轮 `performance.timeOrigin` 断言。全部 102 项通过，25 个采样点的时间原点一致。第 1–24 轮 DOM 为 894、监听器为 1,598。两组全部采样点各有一个活动上下文，活动上下文均有 1,127 个 Buffer、24 个 Texture、61 个 Program、8 个 Framebuffer、3 个 Renderbuffer 和 680 个 VertexArray，缓存贴图的 dispose 监听器最高为 2。

独立组 JS 堆第 1 轮 20.78 MiB，第 16 轮 23.54 MiB，随后回落。第 17–24 轮为 22.00–22.11 MiB，末轮 22.11 MiB。后段 DOM、监听器和活动资源保持稳定，本轮采用 24 轮作为验收窗口。48 轮及差分堆快照沿用既有归因作为历史参考。两组曲线的起始会话不同，CSV 与 SVG 分别展示。[堆曲线](E:/AgehaTech/.r12-shots/r123-d-20261103/heap-trend.svg) · [既有堆归因](E:/AgehaTech/docs/r122-d-heap-report.md)

## 故障注入与设备

- WebGL 不可用时出现三项目列表，实点项目卡片进入详情。
- 使用 `WEBGL_lose_context` 注入丢失，检查遮罩和刷新、项目列表入口。调用原生恢复后遮罩消失，上下文恢复并记录有效 draw calls。
- 拦截贴图后，场景处于 ready 并出现可访问的失败提示。实点浏览入口进入项目列表，重新进入拦截状态后解除拦截，实点“重试”，确认文档重载、贴图请求返回 200、失败提示消失且恢复绘制。
- 注入期间 10 条贴图加载异常、10 次 inspector 拦截失败集中在两个资源拦截阶段。恢复阶段为 0 异常、0 请求失败。正常运行各组均为 0 控制台错误、运行时异常、浏览器错误和请求失败。综合组保留 31 条 Clock 弃用及 2 条着色器精度提示。
- Windows 当前设备检查未发现可用的 Android 或 iPhone，移动结果限于 Chrome 触摸与视口模拟。真机方向切换、后台恢复、15 分钟持续使用和性能留待实机。
