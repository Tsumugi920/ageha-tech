## 2. 下一步优先级的依据

### 验收证据需要补强

- `.r12-shots/r121-prod/14a-pine-spire.png`：前景高树上下出画，无法同时验收完整树冠、树干和根部。
- `.r12-shots/r121-prod/15-rocks-fusion.png`：主要是雪坡和树，目标岩簇接地边界未清楚展示。
- 机位净空脚本检查解析地表，不检查目标完整入画、植被和物件遮挡。通过净空检查不等于完成资产视觉验收；岩壁机位部分采样在岛外，不能据此确认岩壁网格净空。
- `scripts/capture-r121.mjs` 每次导航清空错误，并过滤 `synchronously unmount a root`。现有 `errors: []` 不能证明整轮零错误或历史 React 警告已解决。
- 现有采集固定 high 档、开启 reduced-motion，并关闭或用 CSS 隐藏引导卡和提示。适合美术对比，需要另补无干预的默认体验验收。
- 当前截图报告未保存逐机位状态和渲染统计，无法沿用历史版本的性能结论。

### 比继续扩大资产数量更值得处理的画面问题

- 首页 `01-home-initial.png`：蝴蝶上翼进入导航栏背后，区域名牌覆盖翼面。R12.1 前后均存在，应独立处理构图。

## 3. 分阶段执行

### R12.2-A：补齐验收证据（首先执行）

范围：优先修改截图与验证脚本、报告；只有真实复现功能问题后才另列最小修复。

1. 调整 14a、15，必要时调整 14c；保留旧图，注明变更机位不可直接用于像素前后比较。
2. 给每个机位明确目标：高树须完整展示冠层、树干与根部；岩石图至少两块不同轮廓岩石的接地边界清楚可见。不得通过隐藏地形或物件制造验收图。
3. 按机位和操作阶段保存原始 console error、warn、未捕获异常、请求失败及状态。导航前归档当前阶段，禁止无记录清空或按警告文本过滤。
4. 保留固定档、静止动效的美术对比组，另加无 CSS 隐藏、正常动效、自动档的默认体验组。分别记录首次加载、引导出现、用户正常关闭引导。
5. 将已有 `__AGEHA_WORLD_STATE__()` 与 `__AGEHA_WORLD_INFO__()` 保存进报告，记录视口、DPR、档位、相机、玩家、draw calls 和三角形等。
6. 真实走近和绕行 SignPost，复核名牌是否过大或遮挡；目前仅有风险证据，不能先认定为确定缺陷。
7. 在微起伏较高的雪地检查信灯离地关系、树根和岩石接地。保留现有解析高度契约，发现问题再决定视觉层最小修正。

验收：每张图能证明它声称的目标；全流程日志可追溯；历史 React 警告标明“本次未复现”或复现步骤与处理结果。保留未解决问题，不将其隐去后称零错误。

### R12.2-B：首页构图与固定 UI 安全区

依赖：A 提供可信的默认体验基线。

- 同批检查 1440×900、2560×1440、390×844 的首次进入与关闭引导后构图。
- 对比两种小范围方案：调整初始相机视线/距离，或调整区域名牌的位置/显隐。先出对照，按收益选择改动较小的方案。
- 蝴蝶与 AgehaOS 本体、世界坐标、出生点保持；避免地标与顶栏、名牌的主要轮廓叠压。
- 如修改初始相机，必须保持初始画面与跟随相机一致，首次移动不跳变；相机边界或跟随逻辑发生改动时补针对性回归测试。

验收：三种视口均有完整可辨识的主地标；文字可读；正常移动、旋转、缩放和首次跟随过渡通过。移动端保留摇杆和按钮可操作空间。

### R12.2-C：一段道路与地表融合试点

依赖：B 确定主视角，A 完成实际通行复核。

- 首选北径入口；若首页右前道路的问题更突出，则两者择一，不同时铺开。
- 先识别分离感来源：几何离缝、共面闪烁、材质边界或覆雪过渡。不得仅靠装饰掩盖真实几何问题。
- 优先在视觉边缘处理贴地、局部覆雪和材质过渡，继续使用既有路径采样。
- 保留路线、有效通行宽度、连接端点、高度契约与碰撞；保护 C 径已验收踏板和 A/M 径功能。
- 通过后再决定是否扩展到其他入口，本阶段不承诺全岛道路统一重做。

验收：同机位对比能辨认改善；近地与侧看无悬空、穿刺或闪烁；真实往返通行与相关路径测试通过。

### R12.2-D：完整探索与性能回归

- 实测主岛经 A/M/C 三径到达三项目屿、打开详情、关闭返回；复核传送、返回主岛与茧居所入口。
- 桌面默认档、移动模拟、自动降档和 reduced-motion 分别覆盖；模拟设备结果不作为真机帧率宣称。
- 复用现有性能采集方法，前台稳态记录平均与 p95 帧时间、长帧、draw calls、三角形、DPR 和档位，并注明硬件与采样条件。
- 检查默认动效及反复离开/返回首页后的资源趋势；只有出现可复现瓶颈或资源增长才开展针对性优化。
- 在改动前后使用同环境、同路线对比；性能目标沿用项目简报的桌面争取 60 FPS、低档争取 30 FPS，达不到时如实记录，不用静态截图推断。

验收：测试、TypeScript、ESLint、生产构建分别通过；浏览器日志完整保留；三径与项目详情闭环可复现；性能实测与限制明确。
