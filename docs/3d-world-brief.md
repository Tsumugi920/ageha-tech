# Ageha.tech 3D 世界重构 — 权威需求简报

> 本文件是本次重构的权威规格，依据站长 2026-10-25 的原始需求及 2026-10-29 的技术边界修订。所有设计决策与验收以本文件的最新修订为准；与旧实现或旧蓝图冲突时，以最新修订为准。
>
> **2026-10-29 修订：以项目完善与体验品质为优先。** 站长明确允许使用物理引擎、后处理栈、音效、外部 3D 模型／纹理／HDR 以及其他必要工具、依赖和资产；此前对应的禁止性限制不再生效。技术选择依据效果、兼容性、性能和可维护性，不以零新增依赖或全程序化为目标。原创设计、许可证、真实内容、可访问性与实际验证要求继续有效；技术类别授权不代替付费、发布或共享系统变更的操作授权。

## 1. 目标

把现有传统网页作品集**彻底重构**为一个可自由探索的原创 3D 数字世界。参考方向：bruno-simon.com 的**设计理念**——网站本身是可探索的空间、用户可真实操控场景中的角色或载具、通过场景设计/空间布局/路径/碰撞/物体交互传达内容、项目展示融入环境、以个性视觉建立品牌记忆、探索发现内容同时保留清晰导航。

**禁止**复制 Bruno Simon 的场景、模型、素材、代码或具体设计；必须建立 Ageha.tech 的原创视觉世界。

这不是常规 UI 美化。以下做法均不合格：

- 只把 Hero 图片换成 3D 图片，或右侧加一个 Three.js Canvas；
- 保留原 Hero、导航、统计数据、项目卡片的主体结构，只改颜色尺寸；
- 用发光边框、渐变、毛玻璃面板堆砌假装科技感；
- 只有鼠标视差、旋转模型或自动播放动画，没有真正的探索机制；
- 用静态截图、视频或预渲染背景冒充可交互 3D 世界；
- 删除现有项目内容、路由、功能入口来简化开发。

验收标准：即使去掉所有 CSS 装饰，网站的空间结构、交互方式、内容组织仍与原站有明显区别。

## 2. 必须保留的业务（重构前先审计）

- 三个真实项目（`lib/projects.ts`）：AgehaOS、CS 饰品虚拟投资模拟器、Moss World——名称、描述、技术栈、封面、状态、链接逐项保留。**Moss World 没有任何链接，不得编造**；全部内容受诚实边界约束（不写各仓库 README 之外的宣称，见 `lib/projects.ts` 注释）。
- 路由：`/projects`、`/projects/[slug]`、`/about`、`/tech`、`/contact`、`/articles` 及首页 SEO / 分享元信息。
- About、个人介绍、技术栈、联系方式内容；导航与链接能力。
- 以现有架构和业务数据为起点；允许采用有明确收益的新技术或架构调整，不为模仿参考站无目的重写，也不得丢失现有数据、路由和功能。
- 每次改动同步更新 `tests/` 下相关测试；交付前所有测试与验证全部通过。

## 3. 美术方向

关键词：Ice Blue World / Playful 3D / Floating Architecture / Glass Structures / Spatial Exploration / Premium Creative Portfolio

- 冰蓝、浅青、冷白为主要品牌色；通过深浅变化、环境光、雾效和远景营造空间层次。
- 玻璃、半透明、金属、磨砂、柔和发光材质合理搭配；**不同区域不同材质与色彩层次**，不要全部统一为透明玻璃。
- 有趣味性和识别度的 3D 物件，不要全是标准化科技立方体；场景有完整地形、空间关系、视觉焦点和探索路径。
- 轻盈灵动 + 成熟作品集品质；画面可以丰富但主次分明。
- 不要黑底紫光赛博朋克模板；不靠堆砌发光边框和毛玻璃营造科技感。

## 4. 空间构图

一个具有连续空间关系的 3D 世界（不是互不相关的模型拼盘）：主岛（初始场景 + 核心视觉焦点）、探索路径（道路/浮空桥梁/光带等方向性结构）、项目区（分布于不同位置的展示实体）、远景（漂浮岛屿/建筑群/云层/天空的纵深感）、隐藏区（少量彩蛋或非必要探索）。命名可自定，但空间组织逻辑必须清晰，每区有合理尺度、位置、视觉层级与可达性。

主视觉不能只是放大的背景模型：通过摄影机视角、前中后景、遮挡关系、光照、环境反射建立真实空间感。

## 5. 蝴蝶品牌

蝴蝶是 Ageha.tech 的重要识别元素，应从背景图升级为 3D 世界的重要视觉元素（如引导探索的动态蝴蝶、场景中央能量装置/世界核心、连接区域的视觉线索、与项目或隐藏内容关联的互动对象）。以现有素材（`public/images/` 下 hero 图等）的实际质量和授权为基础决策：高质量 2D 可作为独立空间视觉元素；有条件可用真 3D 蝴蝶；**不要为 3D 化把低质量 2D 硬贴在立体模型上**。必须与场景光照、尺度、景深、运动协调。

## 6. 项目区

以真实项目内容为基础设计场景实体（示例方向，按真实数据调整，不得凭空编造项目功能）：AgehaOS → 未来操作终端/悬浮计算核心/系统控制站；CS 模拟器 → 数据观测站/可视化控制台/动态数据装置；Moss World → 玻璃生态舱/微型森林/可观察生态空间。

三区造型、颜色、环境、视觉记忆点各异，但共享统一美术体系。项目实体必须有真实交互入口（点击或靠近触发详情）。详情至少包含：项目名称、简介、技术栈、预览图（现有封面）、访问项目/查看源码等已有链接。详情内容多可用 HTML 面板或独立详情页承载，不要求全部画进 3D 场景。

## 7. 交互系统（本次重构的核心）

控制方式：

- 桌面：WASD 或方向键移动；鼠标控制观察方向或调优的第三人称摄影机；适当滚轮缩放等辅助控制；明确键位说明；键盘导航与快速项目访问。
- 移动：触摸移动控制、明确虚拟摇杆或方向按钮、触屏友好的交互距离与点击区域、更简单的摄影机与操作、更低模型复杂度与渲染分辨率；必要时提供轻量 3D 或项目浏览模式。目标是可用、稳定、项目访问完整。
- 角色/载具选择要服务 Ageha.tech 自身世界观，不为模仿参考站而机械加汽车。

运动系统：合理加速度、减速度、转向响应；不穿透主要场景物体；处理边界、道路、平台；摄影机不剧烈抖动、不穿模、不瞬间跳变；按移动方向和速度适度跟随；稳定初始视角与清晰探索方向；摄影机与角色控制不冲突。

场景交互（至少实现核心部分）：基本碰撞检测；项目对象悬停或靠近反馈；点击或按键进入详情；可视化交互提示；合理动画与过渡；重定位/返回起点/快速传送；详情返回探索世界；随时打开项目导航。**不要只做悬停变色**。反馈有一致的动画节奏、视觉语言和明确操作结果。

导航与可用性：快速进入任意项目；查看项目列表；返回起点；打开 About 与联系方式；跳过开场动画；不熟悉控制时可查操作说明。首次进入提供可关闭的简短引导，不强制观看长动画。**3D 世界不能成为获取信息的障碍。**

## 8. HTML 信息层（重建而非旧页套壳）

体验流程：简洁有氛围的加载界面 → 进入 3D 世界 → 短暂品牌识别与操作提示 → 自由探索 → 靠近项目出现提示 → 打开详情 → 返回场景或快捷导航。加载界面**真实反映资源加载状态，不用假进度百分比**。

HTML 层内容：简洁品牌标识；不抢主视觉的导航；操作说明；项目快捷入口；项目详情面板；About 与联系方式；加载/错误/低性能提示。冰蓝冷白、适量透明度、清晰排版；只在明确必要时用毛玻璃/边框/发光。**不要把原整套页面直接叠加在 Canvas 上。**

信息层级：一眼分清当前所在区域、可进行的操作、当前选中项目、如何退出/返回、如何跳过探索直接看内容。文字对比度与易用性优先。

## 9. 工程要求

- 先审计后动工。React 项目优先 Three.js + React Three Fiber（与 React 19 / Next 16 兼容的版本），3D 内容 SSR 安全；不强行迁移框架。
- 模块划分（适配现有仓库结构，不为形式堆文件）：World/Scene、Terrain/Environment、Player/Controller、Camera、Interaction、Project Objects、UI Overlay、Asset Loading、Performance。
- 合理模型复杂度与材质数量；重复物体实例化渲染；避免不必要实时阴影/反射/高成本后处理；雾效/环境光/烘焙按需；资源按需加载；处理 WebGL 上下文丢失与资源释放；组件卸载清理事件监听、动画和 GPU 资源；避免 React 高频状态更新重渲整棵树（高频运动用帧循环/引用机制）；禁止无限循环、重复创建对象、失控事件监听。
- 允许为视觉与交互品质引入必要依赖，包括物理引擎、后处理与音频库；核实版本兼容、许可证、加载与运行成本，按实际收益选择，不以依赖大小或数量单独否决方案。
- 允许使用外部模型、纹理、HDR、动画、烘焙资源和资产处理工具，也可与程序化建模混用；新增资产须授权明确并记录来源，不依赖易失效外链。所有资源须统一美术设计与空间构图，**不许简化成基础几何体或外部素材的无序堆叠**。

## 10. 性能与响应式

- 桌面验证 2560×1440、1440×900、1920×1080：初始构图完整、主体不拉伸裁切、远近关系正常、UI 不挡交互对象、项目入口易发现、对比度足够、不同屏幕比例视野合理。用开发者工具查 CSS viewport / 设备像素比 / 实际容器尺寸，**不要把显示器物理分辨率当 CSS 视口宽度**。
- 性能实测：首次加载资源大小、首屏可交互时间、真实帧率与帧时间、GPU/CPU 负载、内存与长期稳定性、低性能设备表现、页面切换/返回是否泄漏。目标：支持 WebGL 的常见桌面设备争取稳定 60 FPS，**但这是实测目标，不是未经实测的既成事实**。低性能设备按实测动态调整渲染比例、阴影、粒子、后处理、远景细节。
- WebGL 不可用或初始化失败：提供可访问的项目浏览降级界面，不显示空白页。
- 无障碍：键盘操作与清晰焦点状态；交互按钮有明确名称；重要项目信息不能只存在于 3D 画面；遵守 prefers-reduced-motion；为无法操作 3D 的用户提供替代导航。

## 11. 验证要求

必须真实运行验证：安装依赖 → 原构建流程 → 测试/类型检查/lint → 本地服务 → 浏览器实际访问 → 检查控制台与网络请求 → 实际操作移动/碰撞/摄影机/交互 → 测全部项目入口与原有链接 → 详情开关返回闭环 → 桌面与移动视口 → 加载失败/WebGL 不可用/低性能/减少动态 → 修复后复测。

**不得仅凭静态代码审查宣称正常运行；环境受限时必须明确说明未验证项，不得伪造测试结果、帧率或截图。**

## 12. 验收标准

- **A 视觉**：原 Hero+卡片布局不再是首页主要体验；首页是完整空间关系的原创 3D 世界；冰蓝品牌与趣味 3D 统一；蝴蝶融入世界观；项目区各有视觉识别度；近中远景与视觉焦点清晰；不靠发光边框毛玻璃。
- **B 交互**：明确操作方式探索场景；移动/摄影机/碰撞实测通过；项目实体有真实交互入口；详情可开关并返回世界；有不依赖探索的快速导航；About/联系可访问；加载/错误/无 WebGL 场景有合理处理。
- **C 业务**：原有项目内容与链接保留；路由保留；未擅自删功能或数据；无明显控制台错误、资源错误或坏交互。
- **D 工程**：构建成功、已有测试执行或注明原因；浏览器完成基本交互验证；2560×1440 与 1440×900 实测；移动视口验证；性能实测并记录设备环境；低性能与 WebGL 失败有降级；无明显资源泄漏或持续性能恶化。

## 13. 实施顺序

审计 → 概念/构图/控制/技术方案 → 可运行核心世界（场景/摄影机/地形/探索对象/基本移动）→ 碰撞/项目交互/详情/快速导航/HTML UI → 原创美术/材质/灯光/动画/品牌视觉 → 响应式/性能/加载/降级 → 构建+测试+浏览器实操+修复复测。

先保证体验闭环真实可用，再提升视觉品质；不要精修孤立模型而没完成场景与交互系统。
